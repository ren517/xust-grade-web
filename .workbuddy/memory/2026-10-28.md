## 服务器部署（ubuntu@VM-0-10-ubuntu）
- 部署目标机：`ubuntu@VM-0-10-ubuntu`（用户 ubuntu，密码用户自输；非之前的 tencent_deploy）。项目根目录 `/home/ubuntu/python`（app.py 直接在其下，不能多套一层）。
- 运行方式：`cd /home/ubuntu/python && bash deploy.sh --https`（deploy.sh 已生成在项目根：建 venv + 装依赖 + 以 HTTPS_ONLY=1 起 uvicorn 绑 127.0.0.1:8000）。
- nginx 在**同一台** ubuntu VM：`/etc/nginx/sites-available/grade`（已软链到 sites-enabled/grade），反代 127.0.0.1:8000；域名 `grade.ren517.xyz` + `grade.q77u.top`（certbot 证书，443）。
- HTTPS_ONLY 开关：本地 http=0，公网 HTTPS 部署必须 `export HTTPS_ONLY=1`（deploy.sh --https 已设），否则登录 cookie 不下发、一直弹回登录页。
- 踩坑：`.gitignore` 排除了 `config.py` 和 `key.key`，**不能用 git clone 部署**，必须 `tar --exclude=venv --exclude=__pycache__ .` 整包 scp 再解包，否则缺文件启动即崩。
- 排错经验（重要纠正）：`/users` 浏览器返回 `{"detail":"Not Found"}` 的真正根因是**服务器 uvicorn 进程跑的是旧版 app.py（无 /users 路由）**。`curl -I`（HEAD、无 cookie）得到的 302→/login 只证明 AuthMiddleware 在跑（中间件在路由之前执行），**不能证明路由存在**——已登录浏览器 GET 才会暴露路由缺失。正确排错顺序：先 `grep -n '@app.get("/users")' app.py` 确认磁盘代码版本，再 `bash deploy.sh --https` 重启进程（脚本会 pkill 旧进程）。uvicorn 无热加载，更新代码后必须重启。
